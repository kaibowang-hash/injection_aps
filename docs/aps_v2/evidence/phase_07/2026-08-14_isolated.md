## 2. 数量和求解契约

- DFS 先完整建图和环检测，再按拓扑顺序计算；BOM 环或损坏主数据形成 `Never Override` Hard Blocker。
- 同物料生产节点在 Run 内合并，但每个 root demand 保留 `gross_by_root`、库存/WIP/生产分配和 parent/child Pegging，可从根需求下钻也可从半成品反查所有根需求。
- 根需求分配优先级为 P0 → P1 → P2、交期、服务优先级和稳定 key；损耗、UOM 换算、BOM output quantity、批量取整和 excess 显式保存并守恒。
- 只有配置为 APS 可生产的中间品建立 machine demand；Raw Material 是 informational leaf，库存为 0 也不影响可行性、Apply 或指纹。
- Solver 输入包含不可变 BOM decision 和 precedence；正式 Solver 与 fallback 都保证 child completion 不晚于 parent start，Apply 前由独立 Validator 再验证。
- Campaign 与 BOM 组合时 precedence 只约束单一 capacity owner，不重复占用机台/模具。

## 3. BOM 选择、库存/WIP 与工单

- 默认使用物料的已提交默认 BOM；只有 `Explicit Approved Alternative` 才可替换，必须记录审批人、时间、理由、BOM modified 和 fingerprint。
- 替代 BOM 必须是当前 root 图可达的活动已提交 BOM；修改、停用或引入环后必须重新审批/重算。
- 半成品库存仅使用明确 Finished Goods/Work In Progress 仓和配置的车间 WIP 仓，按 hard available 扣减各类预留，并扣减其他活动 Run 在正式 WO 前的 Pegging claim。
- WIP 只承认已提交、未完成、且没有 SO/Result/Run 所有权的旧工单；一个 expansion 内库存/WIP 只分配一次。
- 工单 Proposal 和 Work Order 携带 Result 的 exact selected BOM/fingerprint/source；建 WO 时再校验当前 BOM 指纹，不会回落到另一张 BOM。
- 保留现有 BOM 上的必填自定义字段规则；集成 Fixture 显式满足 `custom_temporary_bom="No"`，未修改或删除任何用户定制。
