## 2. 计算和流程契约

- `remaining_good_qty = max(planned_qty - actual_good_qty, 0)`；Scrap 单独显示，不得错误减少尚需生产的良品。
- 有至少 3 个有效样本时使用最近 5 个样本的中位速率；已开工任务样本不足才标记 Standard Fallback。未开工未来任务使用标准节拍是正常计划，不触发虚假确认。
- 数据新鲜度优先取最新有效 Production Allocation 时间，再取 WO 修改时间；超过设置阈值必须由 GMC 确认。
- 局部 CP-SAT 固定执行中、转料、完成、锁定任务，执行 Machine/Mold NoOverlap，保留当前资源顺序并最小化开始时间偏移。
- Cycle 创建前刷新生产与交付实际；fingerprint 同时纳入最新有效 Schedule Revision、Production/Delivery Allocation 和 Run 修改时间。零容量 Downtime 作为精确 Machine/Mold blocked interval 进入局部 CP-SAT。
- 普通 Cycle 的最早可移动时间为下一班次；Emergency 只允许 Manufacturing Manager，且必须填写原因。
- Cycle 只保存 Baseline、Forecast、Diff；生成独立 `APS Shift Schedule Proposal Batch` 后逐行审核。GMC Apply 在同一请求事务中先应用 WOS Proposal，再更新 Segment Current Plan；Original/Baseline 永久保留。
- System Manager 不能替代 GMC 做业务风险批准；PMC 可生成草案，GMC 确认/批准/应用，Manufacturing Manager 执行 Emergency。

- 页面同时展示 Current、Forecast、Proposed、差异类型、冻结状态和原因，并可打开标准 Shift Proposal 明细审核。
- 新增 `refresh_shift_actuals`、`generate_replan_proposals`；并提供规格中的 `create_shift_replan_cycle`、`analyze_shift_replan`、`get_shift_replan_diff`、`generate_shift_replan_proposals`、`apply_shift_replan_proposal` 标准名称。既有短 API 保留兼容，所有写 API 继续执行指纹和文档 scope 检查。
- WOS 和 Scheduling Item 写入 `custom_aps_replan_cycle`，Shift Proposal Batch 保存 `replan_cycle`。
