# Phase 6 隔离环境工作证据（2026-08-14）

## 1. 结论

Phase 6 已完成 Family Mold 联产品 Production Campaign、共享产能、分产出工单/WOS/实绩血缘和原子审核链。所有数据库迁移与测试只在 `aps-opt-fixture.localhost`；`jce.1` 零访问、零写入。

## 2. 计算与数据契约

- Campaign 模次为 `max(ceil(required_i / output_per_cycle_i))`；每个物理产出为 `cycles × output_per_cycle_i`，Demand covered 和 Excess 分开保存。
- 单一产出有需求时仍建立其他可靠产出的 Result、Segment、Campaign Output、WO 与说明；多个产出都有需求时不生成“被带出”误导说明。
- Solver 只创建一个 capacity-owner task，但按每个产出的交期、P0/P1/P2、优先级、固定准时/延期数量分别计算交付目标和指标。
- Primary Segment 是唯一机器/模具产能所有者；`Family Co-Product` Segment 只承担本产出数量、WO/WOS 和执行血缘。冻结 WOS 通过 `custom_aps_capacity_owner` 去重，重叠区间在 Solver 输入前合并。
- 旧 Family Co-Product 只有在 Campaign Output、Result、capacity owner 三方精确一致时才可计数量；旧版模糊 credit 继续 fail closed。
- 同一 Run、同一 Family 输出存在多个 Result 时不猜测，要求先合并需求所有权。

## 3. 既有生产/出货流程兼容

- 仍是“工单建议审核 → 工单 → 工单排产/WOS → 工单入库 → 出货计划分配订单 → 销售出库”。
- Campaign 不替代或改写出货计划、Delivery Plan、Delivery Note；只为共享生产活动提供准确的生产侧血缘。
- 每个产出一张 WO；Campaign WO 明确允许无 SO，并写入 Campaign、Output Role、Capacity Owner、Commitment、Result 和 Source Reason。
- WO Proposal 选择任一 Campaign 行时服务端自动扩展全组；Apply 在一个事务中整组创建，任一失败整组回滚。直接绕过 Proposal 创建 Campaign WO 被拒绝。
- 每个产出一条 Scheduling Item；同一物理时段可位于同一 WOS，但只有 Primary 拥有机器/模具产能。
- Manufacture/Production Allocation 通过各产出 WO/Result/Segment 独立回写 Campaign Output good/scrap；不把主 WO `produced_qty` 复制给联产品。

## 4. 调整与重排

- Shift Replan 只把 Campaign capacity owner 当作可移动任务，派生产出不形成第二个重排任务。
- owner 移动后同步 Campaign 与全部派生 Segment 的 Original/Current/Forecast/资源时间；WOS Proposal 的 owner override 同步投影到所有产出。
- Campaign 直接 Resize/Cancel 被阻止，必须重新运行 Solver，避免破坏固定 yield 和数量守恒。

## 5. UI/API

- Work Order Proposal 增加 Campaign、Output Role、Demand Commitment、Capacity Owner、Excess 和 Source Reason。
- Proposal 表单新增 Campaign 摘要，明确“一段共享产能、整组原子审核/应用”；服务端保证分组规则，不能通过手工 API 选择绕过。
- Shift Proposal 和 Scheduling Item 保存同一 Campaign/Output Role/Capacity Owner，可供 Phase 8 Gantt 聚合成单条 Campaign bar。
