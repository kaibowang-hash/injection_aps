## 2. 关键计算契约

- 需求视窗严格为 `start_date + horizon_days - 1`；更早仍未结的 P0 作为 Overdue 纳入。
- Recovery 只提供欠量回补的排程空间，不加载新的 Recovery 日期需求。
- Freeze、Restricted、Recovery 分开存储并进入 Run 快照；不得用一个 horizon 混写。
- V2 状态只有 `Ready`、`Acknowledgment Required`、`Hard Blocked`、`Applied with Exceptions` 等受控状态；普通产能欠量需要确认但不构成硬阻塞。
- 原料覆盖结果单列为 advisory；不进入可排数量、就绪状态、分析指纹、Apply 锁或资源重验。
- Hard Blocker 按注册策略处理：必须修复、限时覆盖、仅排除或风险确认；不存在 `Force Apply All`。
- 部分释放只排除受影响 Commitment/Result，其余可行排程可应用；排除记录、原因、操作者和时间可审计。
