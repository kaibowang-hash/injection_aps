## 2. Progress V2 数据契约

- 默认使用“当前有效跨 Run 投影”：每个 Demand Identity 读取其唯一 `formal_owner=1 / owner_state=Owned` 的当前 Commitment，不按旧 Run 状态或修改时间粗选。
- 用户显式选择 Run 时返回“Single Run”，页面显示单 Run 警告；不会借用另一个 Run 的 owner 计划。
- 明细和日期单元格分别返回 Schedule、Original/Current/Forecast、Actual Good/Scrap、Delivery Plan、Delivery Note、Stock、Shortage/Recovery、状态/原因和精确来源。
- Original/Current/Forecast 是独立比较层，不相加为 supply；Delivery 只采用有效 APS Delivery Allocation，旧 schedule delivered 差额单独标识。
- 每个 schedule page 最大 200 行，矩阵可见列最大 31，范围最大 366 天；API 返回分页、列窗口和运行耗时。
- 状态分为 Delivered、Stock Covered、On Track、At Risk、Late、Uncovered、Unknown；Identity/owner/守恒异常 fail closed 为 Unknown。

真实集成建立两条 Demand Identity，由两个不同 Formal Run 分别拥有，并验证默认视图同时使用两个正确 owner；同时验证 100 Schedule = 20 DN + 10 Stock + 70 Current Plan 的守恒、DP=90、Actual Good/Scrap=30/2、延期需求 Recovery=20。

## 3. Gantt/UI

- Gantt 后端返回 Original、Current、Forecast、Actual 时间和 Campaign outputs；机器视图将一个 Campaign 聚合为一个 owner task，其他输出标记 derived。
- Scenario Comparison 同时读取 Solver scenarios 和 Solver Job 中审计保存的 Legacy Trial baseline，展示 Legacy/V2/delta；Trial 明确只读，只有 Formal Run 可 Apply。
- 机器 UI 过滤 derived bar，Campaign 展开显示每个输出的周期、计划、覆盖、Excess、实际、Result 和 WO；派生输出不能单独拖动。
- Progress 在 Flag Off 时继续只调用原 `get_customer_schedule_progress_data` 并进入原 Legacy render；Flag On 时同一接口服务端安全分派 V2，避免新增可见调用和旧响应覆盖。
- UI 运行时门禁模拟 Detail/Date Matrix、分页/虚拟列、11 层单元格、精确下钻键、Campaign 折叠和四层 Gantt；静态门禁覆盖翻译、空状态、禁用原因和源码安全。
